# 客户案例脱敏方法论（Case-Study Guideline）

> 用途：把「做过的活」安全转成公开案例证据，守住客户保密边界与商业底线。
> 当前状态：站内已上线的 /case-studies 为**能力示例**（基于设备台账，讲「按我们的设备与流程能做什么」），并非客户项目档案；首批真实客户案例等台账口径确认后按本文档发布。

## 一、脱敏四原则
1. **客户代号化**：不出现客户公司名、logo、订单号。一律写「某半导体设备厂商」「某储能集成客户」或代号（客户 A/B/C）。
2. **参数范围化**：腔体尺寸、吨位、真空度写区间或量级（如「数吨级」「1×10⁻⁹ Pa·m³/s 量级」），不写单台精确值。
3. **不泄订单细节**：价格、交期天数、批量数量、图纸关键尺寸、特殊工艺参数一律不进公开页。
4. **发布前老板确认**：每条案例发版前由老板确认口径（哪些项目可写、保密边界到哪），确认后再上线。

## 二、案例条目结构模板（与 /case-studies 卡片字段对应）
\`\`\`
t   （卡片标题）   如「数吨级 304L 真空腔体」
x   （描述）      材料+单件量级+工艺链（台账内设备）+验收方式+交付物，全部为可证实项
tag （标签）      如「重型腔体」「焊接与检漏」
img （配图）      使用 /photos/ 下脱敏实拍或能力图
\`\`\`
写不实的字段宁缺毋滥：不编「效率提升 30%」等无据数字，不写「行业领先」。

## 三、能力示例 vs 脱敏案例（术语纪律）
- **能力示例**：按设备台账陈述「能做什么、怎么验收」，不指向任何具体客户。当前首页与 /case-studies 全部为这一层。
- **脱敏案例**：真实做过的活 + 客户代号化 + 参数范围化。台账口径确认后，复用同一页面结构与 JSON-LD 结构补入。
- 两类的 JSON-LD 语义保持诚实：能力示例用 ItemList/Article；只有拿到真实可写项目才用 CaseStudy 类型。

## 四、联动红线（与全站一致）
- 不写「ISO Class 洁净室」（用「受控洁净焊接环境」）。
- 认证（ISO9001/EN1090/3834）= 推进中，不写成已获证。
- 能力只写设备台账之内；不承诺整机交付。
- 编辑日历、案例口径变更记录在 docs/content-calendar.md。
